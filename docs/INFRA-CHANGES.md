# Changes made to the provided `infra/` Terraform

> **For review by the workshop organisers.** This project builds inside the
> `coding-workshop-participant` scaffold and deliberately does not author its own
> infrastructure. Three provided files have been modified; everything else in
> `infra/` is untouched. Each change below states what it does, why, and what
> happens without it.
>
> If any of these is not permitted, say so and it will be reverted — items 2, 3
> and 4 have workarounds; item 1 does not.

## 1. `cloudfront.tf` — replace the 404 rewrite with a scoped SPA router

**Removed** the distribution-wide `custom_error_response` block that mapped
every 404 to a 200 serving `/index.html`. **Added** an `aws_cloudfront_function`
(viewer-request) attached to the **default behaviour only**, rewriting
extension-less paths to `/index.html`.

**Why.** The scaffold's block applies to every origin, including the API. A
genuine "incident not found" would reach the browser as **HTTP 200 with a page
of HTML** instead of 404. The Full Stack guide requires "404 for not found" and
consistent JSON error responses, so the scaffold's default directly conflicts
with the stated evaluation criteria.

**Without it.** Either the SPA loses deep linking and page reloads, or the REST
API cannot report 404 correctly. There is no configuration that keeps both,
because CloudFront custom error responses cannot be scoped to one behaviour.

**Assessment.** Required. This is the only change without a workaround.

## 2. `lambda.tf` — `memory_size` 128 MB → 512 MB

**Why.** Importing FastAPI, SQLAlchemy and psycopg exceeds 128 MB. Lambda also
scales CPU with memory, so 512 MB materially reduces cold-start time.

**Without it.** The function runs out of memory during import and every request
fails.

**Assessment.** Required for a Python web framework. Could be lowered to 256 MB
if 512 MB is considered excessive. Cost impact is proportional to duration and
negligible at workshop traffic.

## 3. `locals.tf` — generate `JWT_SECRET` and inject it

**Added** a `random_password` resource (64 characters) and one entry in
`local.env_vars`, so the signing key for the API's access tokens is generated by
Terraform and passed to the Lambda as an environment variable.

**Why.** The application signs JWTs and needs a secret that is never committed.
The scaffold already injects `POSTGRES_*` this way; this follows the same
pattern. The value lives only in Terraform state, in the private state bucket.

**Without it.** The signing key would have to be committed to git, or the app
would fall back to a default published in the repository. The application
refuses to start in a deployed environment if the secret is missing or weak
(`backend/v1/app/config.py`).

**Assessment.** Required in some form. AWS Secrets Manager is an alternative
(the IAM boundary permits `secretsmanager:*` on scoped ARNs) but would need a
VPC endpoint, since the Lambdas have no outbound internet route.

## 4. `cloudfront.tf` — enable `compress` *(proposed, not yet applied)*

Setting `compress = true` on the cache behaviours.

**Why.** CloudFront defaults compression to off. The frontend bundle is 790 kB
raw versus 251 kB gzipped, paid on every cold visit — and it grows in the
remaining phases, which add a data grid and a charting library.

The self-hosted fonts shipped alongside it are *not* part of this case: woff2
is already compressed and CloudFront will not shrink it further. The saving is
on the JavaScript, CSS and HTML only.

**Without it.** The app works, just slower on first load.

**Assessment.** Optional. Held back pending this review precisely because it is
a performance improvement rather than a correctness fix.

## Anything else we should know about?

Two scaffold behaviours were left alone deliberately, but are worth confirming:

- **`backend/*/requirements.txt` auto-discovery.** Every matching directory
  becomes a Lambda with a public, unauthenticated Function URL. This project
  ships exactly one service (`backend/v1/`) to keep one public surface.
- **Aurora `min_capacity = 0`.** The cluster sleeps when idle and takes roughly
  15 seconds to wake, so the first request after a quiet period may time out.
  Left as provided; worth knowing before a live demo.
